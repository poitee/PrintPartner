# GRE-292 manifest API availability

## Source and version

This document describes the manifest export portion of GRE-292. It does not close the ticket.

The baseline is main commit `f00471f13d2f0e69631d3130e594b9244f93e01d`, with web package version `3.3.0`.
At that source snapshot, submission draft export returns HTTP `200` with fabricated YAML and the issue text "Community manifest draft (web stub)."
That response is not a usable community submission bundle.

The correction described below is unreleased. No released version or deployed instance is claimed to contain it.
The web package version remains `3.3.0`. Package identity alone does not distinguish the baseline from this change.

## Submission draft export

Both `POST /manifest-registry/export-draft` and `POST /api/v1/manifest-registry/export-draft` return HTTP `501` after the configured authentication checks:

```json
{
  "code": "manifest_export_draft_unsupported",
  "detail": "Community manifest submission draft export is not supported by this web API."
}
```

The response contains no submission YAML, metadata YAML, slug, or issue body.
The operation reads no Source, Plan, manifest, or warning state.
An authenticated request receives the same response with owned IDs, foreign IDs, missing IDs, an empty object, or no body.
Fastify's normal request parsing and size limits still apply.

When authentication is required, a request without credentials returns HTTP `401` with `{"detail":"Authentication required"}`.
The export route is not registered under `/api/v2`. An authenticated POST to that path returns HTTP `404`.

No typed caller invokes either exposed POST path in this source snapshot.
`fetchManifestRegistry` calls `GET /manifest-registry` and remains available.

## Available manifest reads

The embedded registry routes remain available at `GET /manifest-registry` and `GET /manifest-registry/:slug`.
The Source manifest read at `GET /sources/:id/repo-manifest` returns stored repository YAML when present.
The owned Plan read at `GET /plans/:id/kit-manifest` returns the stored kit manifest.
These reads do not produce community submission bundles.

The export tests use a real Source manifest, a stored kit manifest, and a missing-source warning generated by kit import.
They do not establish that the separate manifest-warning API computes real warnings.

## Remaining GRE-292 work

These handlers retain placeholder success responses at the baseline and are outside this change:

- `GET /sources/:id/has-manifest` always reports `has_manifest: false`.
- `GET /sources/maintenance` returns empty maintenance collections.
- `GET /plans/maintenance` returns an empty warning collection.
- `GET /plans/:id/manifest-summary` returns zero counts and empty option groups.
- `GET /plans/:id/manifest-warnings` returns an empty warning collection.

Their ownership checks, truthful-state or unsupported behavior, exact stale callers, tests, and version availability remain separate GRE-292 gates.
