# GRE-487 replay receipts

Run the fixture from `web/` with Node 22 and installed workspace dependencies.

```sh
node --conditions=development --import tsx scripts/desktop-parity/gre487.mts --enabled --engine=ts --format=json
```

`GRE487_DELAYED_PATCH=1` also enables the fixture. Without either activation, the fixture stays disabled. `--format=json` selects output only. Omit it for the existing text output.

The JSON mode writes one `gre487-replay-v1` document to stdout. Diagnostics go to stderr. Its `kind` determines its fields and process exit code.

- `disabled` exits 0 and marks `typescript` and `rust` as `not-run`.
- `unavailable` exits 2, identifies the requested `engine`, and marks both engines as `not-run`.
- `ts-pass` exits 0, marks `rust` as `not-run`, and includes `runs` and `evidenceSha256` as two-element arrays.
- `fail` exits 1 and contains an `error` string. It has no replay bodies or passing hashes. A replay may have started before failure.

A `ts-pass` receipt requires two independent real TS route and SQLite replays to complete and match. Each run contains the held D0 request, three fresh edits, the stale refusal, draft reopen, final save, and accepted Review reopen. The assertions require `409 draft_changed`, exact logical database and fixture-file no-write, and surviving choices after save and reopen.

Each `evidenceSha256` entry hashes the UTF-8 result of `canonical(runs[index])` from `model.mts`. Canonicalization sorts object keys recursively and preserves array order. Replay bodies replace their temporary data-directory prefix with `$DATA` through the existing normalization policy.

An exact `--format=json` also selects JSON reporting for CLI argument errors, including unknown or repeated arguments. Runtime or loader failures before the CLI starts cannot emit a receipt.

Rust draft/edit/save services are absent. Enabled `--engine=rust` and `--engine=both` remain unavailable and exit before importing the TS scenario. These receipts prove TS behavior only. They do not establish Rust parity, Rust guard sensitivity, historical TS failure comparison, or browser click timing. GRE-487 remains In Progress.

Run the opt-in CLI checks separately.

```sh
node --conditions=development --import tsx --test scripts/desktop-parity/gre487.test.mts
```
