# GRE-402 remaining scope

This change admits the Node Source Sync operation before HTTP aliases, MCP `start_sync`, job execution, and watcher timers. It rejects conflicting worker/startup ownership, unknown owners, and an unsupported Rust assignment. It does not finish GRE-402.

Desktop `CoreRuntime` startup persists `source-sync-admission.json` in the storage-lease data directory before bind and before the compatibility process. `Gateway::start` repeats the bundled manifest check in memory and does not choose a second directory. Source Sync execution stays on Node until the Rust executor is integrated.

`ownership::manifest` combines claims from `ownership-manifest.json`, `operations.json`, and the Source Sync record. Each HTTP registry entry claims its route through `owner` and `operation`. Admission accepts only `compat` registry ownership and parses it as Node ownership. Explicit manifest groups take precedence, and HEAD inherits its GET group. A route needs no separate participant entry when the registry already claims it. Every resolved operation still needs an explicit resource state. Other Node participants use the manifest's explicit groups or `node_participants` lists.

The index covers 839 desktop-registered Fastify routes and aliases, 89 assistant tool dispatch cases, 39 confirmed assistant actions (`start_sync` keeps its Source Sync id `mcp.start_sync`), 3 MCP-only tools, 10 job kinds and 9 startup, worker and migration hooks. A double claim, an alias group split across operations, a claim on a refused or unregistered route, an unsupported owner, or an unknown kind fails admission. A lookup for an unclaimed participant fails closed. The census test derives each set from source and fails when the combined index misses a participant or claims one that no longer exists. Desktop startup admits the index only when `desktop_rebuild` is on. Outside `source.sync`, HTTP aliases share registry operation groups. Other Node participants are still each their own operation.

## Live-format rollback

A rollback returns an operation from Rust to Node after Rust may have written its resources. `OwnershipIndex::admit_rollback(participant)` admits it only when Node reads every format Rust leaves behind. Code maps each resource to one format: every table to `sqlite-schema`, `source-workspace` to `source-revision-workspace`, `source-covers` to `source-covers`, `kit-catalog` to `kit-catalog`, `path-hints` to `path-hints`, and `community-manifests` to `community-manifests`.

The manifest's `live_formats` object declares `node_reads` and a required `rust_writes` for each format. A positive Rust version admits rollback when it is at most Node's. The explicit string `"none"` means Rust never writes the format by design and admits rollback. JSON null means the writer is unknown and refuses with `IncompatibleLiveFormat`. The typed `RustWrites` enum preserves these three states while keeping the existing error types. Missing declarations, zero, unknown strings and other invalid types fail admission with `Malformed`; an omitted writer never becomes `"none"`.

Node `currentSchemaVersion` is 34 and Rust `pp-storage` stamps 35 after its jobs schema. Both sides read and write source snapshot manifest version 1. The Source Sync record's `source-revision-workspace-v1` must match the declared workspace version. Rust never writes covers, catalogs, path hints or community manifests, so `source-covers`, `kit-catalog`, `path-hints` and `community-manifests` declare `rust_writes: "none"`. `no_writer_declarations_have_family_literal_rules` maps every manifest `"none"` format to family literal tokens and checks that they equal the ast-grep regex's alternation set. The `no-writer-family-literal` rule matches family path components case-insensitively in Rust string literals outside the ignored test paths. The ast-grep baseline ratchets their count; a new literal requires updating the declaration, justifying a baseline increase, or adding a reasoned per-line `ast-grep-ignore`. Inline `#[cfg(test)]` code naming a family also needs a reasoned per-line suppression. This checks literal counts, not write operations, dynamically assembled family names, or escaped or split spellings. Rust `pp-storage::open_at_with_effect_policy` creates the empty `covers` directory but writes no cover files. Node `lib/source-cover.ts::ensureSourceCover` publishes the image and metadata, and the Node source routes call it.

`kit-catalog` uses a fixed `node_reads: 1` to name the existing object-shaped JSON/YAML loader contract. `services/kit-catalog.ts::loadKitCatalog` does not validate a catalog version or define a maximum readable version. Its empty fallback has `version: 1`; this is not a reader-version ceiling. A future version-aware loader must update this declaration and its test together.

`path-hints` declares `node_reads: 1` because `services/path-hints.ts::readPathHintRules` rejects every version except 1. `community-manifests` declares a fixed `node_reads: 1` for the unversioned object loader contract. `services/manifest-apply.ts::loadManifestYaml` ignores `format` and `version`; the builder's synthesized v2 YAML does not constrain the reader. Real reader tests pin acceptance of absent, old, future and nonnumeric versions and rejection of path-hint versions other than 1. A reader contract change must update these declarations and tests together.

Reviewed operations with tables, including `tool.get_plan_snapshot`, `tool.get_build_recipe`, and `tool.get_build_workflow`, refuse rollback on `sqlite-schema`, because the bundled Node refuses a schema newer than 34. With SQLite compatible, plan snapshot, build recipe, build workflow and `source.sync` admit rollback. `tool.get_kit_catalog` admits rollback against the bundled manifest because its only resource is the catalog. `tool.get_workflow_help`, `tool.web_search`, `tool.fetch_web_page`, `tool.get_job_status`, `tool.check_hardware_interfaces`, `tool.propose_add_custom_filament` and `tool.propose_create_build` admit rollback with empty sets because none touches tables, application files or live formats.
